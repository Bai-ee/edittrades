## Code

- `scripts/research/edge/lib.js` — appended `macd(close, fast=12, slow=26, signalP=9)` and
  `obv(bars)`. Append-only; no existing export changed.
- `test-macd-obv.js` — hand-computed fixtures (small periods so the EMA seeding is fully
  traceable by hand) + append-future invariance for both indicators + a structural warmup-boundary
  check on the real fixture data. `node test-macd-obv.js`.
- EMA seeding (inherited from `ema()`, unchanged): the first `p-1` values are NaN, the value at
  index `p-1` is the simple average of the first `p` inputs, and it recurses with `k = 2/(p+1)`
  after that. `macd()`'s signal line is seeded from the macd line's own **first finite index**,
  not index 0 — otherwise the signal EMA's SMA-seed would sum leading NaNs from the slow EMA's
  warmup and stay NaN forever.

## H1 — MACD cross entries

**Definition (locked):**
- Timeframes: 4h and 1h, independently, on the deep2y fixture (`test/fixtures/history/deep2y-2026-09-26`,
  BTC/SOL/ETH, 2024-10-01 -> 2026-09-27), same data families.js/run.js use.
- Signal: `macd(close, 12, 26, 9)` computed on the timeframe's own closed-bar closes. Long entry
  on the closed bar where the macd line crosses above the signal line (`macd[i-1] <= signal[i-1]
  && macd[i] > signal[i]`); short entry on the mirror cross below. Entry fills at the next 5m bar
  open at/after that bar's close time (`lib.simulate`, no lookahead — same convention as
  `families.js`).
- Stop: `1.5 x ATR(14)` of the same timeframe, from the signal bar's close.
- Target: 2R (`entry +/- 2 x risk`), set at trade open.
- Exit: opposite cross (checked on the next closed bar of the same timeframe once macd is back on
  the other side of signal — equivalent to a fresh opposite cross, same pattern as F3's SMA20
  `exitAt` in `families.js`) **or** the 2R target **or** a timeout backstop (4h: 60 days: 1h: 20
  days) — whichever comes first. One position at a time per symbol/timeframe (`busyUntil` gate,
  same as `run.js`).
- No regime filter. Long and short reported together and split out.
- Costs: perps base (`COSTS.base` — 0.20% long / 0.14% short round trip + 0.02%/h borrow).
- **Spot variant (4h only):** long while `macd(4h close) > signal`, flat (cash) otherwise, no
  shorts. Data: `var/edge/4h-long/{BTC,ETH,SOL}_4h.json` (same source as Card 1's SMA200 study,
  longer history than the deep2y fixture). Cost: 0.15% per side, decide at bar close j-1, fill at
  bar j's open (same fill convention as `sma4h-trend.js:runSma4h`, reimplemented locally since
  `runSma4h` is hardcoded to an SMA signal and is not mine to edit). Benchmark: Card 1's SMA200
  net CAGR and buy-and-hold, same symbols/windows.
- **Split:** train = entries before 2026-01-01; holdout = 2026-01-01 -> 2026-09-27, run only for
  configs that pass train. Five candidate configs total across H1 (4h-perps, 1h-perps, 4h-spot
  bundled as one config each since long/short are reported together): **max 2 promoted to
  holdout**, chosen by train-phase net R (perps) / beat-B&H margin (spot).
- Stats: `stats()` (mean, median, simple IID t = mean/(sd/sqrt(n)), win rate) — the existing
  `lib.js` function, same one `run.js` uses. This is a naive IID t-stat; trades are not
  independent (autocorrelated regime, overlapping symbols), so Card 3 R3's block-bootstrap
  significance test supersedes this once WP3 lands. Flagged, not fixed here.
- Break-even: `perTrade()`-style calc (same formula as `scripts/research/edge/breakeven.js`,
  reimplemented locally rather than imported — importing `breakeven.js` would execute its
  top-level file reads/writes as a side effect): break-even round trip with and without 0.02%/h
  borrow, max tolerable borrow, vs. actual (0.20%/0.14%, weighted by side mix).

## H2 — OBV confirmation of Donchian breakouts

**Definition (locked):**
- Base trades: the existing F1 4h Donchian breakout family from `var/edge/train-r1.json`
  (train-phase, entries before 2026-01-01, generated by `run.js`/`families.js`, deep2y fixture) —
  **read only, not regenerated** (`var/edge` is a shared read-only symlink in this worktree).
  Configs: `F1-don-4h-N20`, `F1-don-4h-N20-reg`, `F1-don-4h-N55`, `F1-don-4h-N55-reg`, each at
  `k2` and `k3` (8 configs total; `-reg` = daily EMA50 regime filter on, per `families.js`).
- OBV confirmation definition (**one**, chosen over the alternative below): confirmed if OBV
  itself breaks its own prior-20-bar Donchian channel in the breakout's direction, evaluated on
  the same closed 4h decision bar as the price breakout — `obv[i] > highest(obv[i-20..i-1])` for a
  long breakout, `obv[i] < lowest(obv[i-20..i-1])` for a short breakout. This mirrors the price
  rule's own Donchian-N20 breakout definition (same look-back, same "channel break" logic, applied
  to volume instead of price), which makes it a cleaner apples-to-apples confirmation test than
  the alternative ("OBV slope over 20 bars", i.e. `obv[i]` vs `obv[i-20]`, which is a weaker
  trend-direction check, not a breakout-strength check). The OBV window is fixed at 20 for every
  config (including the N55 price breakout), since the question is "does a volume breakout
  coincide with the price breakout", not "does OBV lag N".
- Matching: each trade's decision bar is recovered from its `entryTime` (`=b.ct[i]` exactly, the
  signal bar's close time per `run.js`) via `lastClosedIdx(bars4h, entryTime)` on 4h bars reloaded
  from the same fixture/symbol.
- Split: confirmed vs. unconfirmed vs. all, per config. Compare gross R (mean), net R (mean, t),
  win rate, n.
- Train-phase only (the source data already is); **no holdout run for H2** — this is a filter
  applied post-hoc to an existing registered family, not a new discovered signal, so promoting it
  to holdout is deferred to a future WP if train-phase shows a real split.
- Break-even: same `perTrade()`-style calc as H1, per split (confirmed/unconfirmed/all).
