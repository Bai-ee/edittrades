# S1 Agent H — 2-year 1-minute history

Owner ask (`docs/PROMPT_S1_EDGE_SEARCH.md` "H — long 1-minute history"): find out whether a
longer lookback surfaces an edge the 85-day `deep60-2026-09-24` fixture doesn't show.
Research only — no engine change, no product change, no deploy.

## Correction (2026-09-27, from the orchestrator, cross-referenced by the exits-study agent)

The first cut of this fixture copied `5m`/`15m`/`1h`/`4h` verbatim from
`deep60-2026-09-24`, which only spans ~85.5 days. `loadHistoryDir` requires every
`NATIVE_TIMEFRAMES` file (`services/marketData.js`: `1m/5m/15m/1h/4h/1d` — only `3m` is
derived) to exist, and `scripts/replay.js`'s `replaySymbol` won't call a rule/build until
**every** replayed timeframe has `replay.minComputeCandles` (200) closed candles. With
`4h` only reaching back to 2026-05-27, that silently bounded every downstream replay
(`replay.js`, `replay-rules.js`, `swing/run.js`'s multi-tf rules) to the same ~85-day
window `deep60` already covers — defeating the point of a 2-year fixture. (This also
caused a first, worse bug during my own testing: I'd initially missed copying `5m`
entirely, which made `replay-rules.js` find **zero** eligible closes across the whole
span — see the L0 section below for how that surfaced.)

**Fix:** `5m`/`15m`/`1h`/`4h` are now DERIVED from the full 2-year `1m` Binance series via
production's own `services/marketData.js` `aggregateToBuckets` (UTC-epoch-aligned buckets,
`open`=first, `high`=max, `low`=min, `close`=last, `volume`=sum, `timestamp`=bucket start,
`closeTime`=bucket end — an incomplete trailing/leading bucket is dropped, matching
production semantics exactly since it's the same imported function, not a reimplementation).
`1d` is untouched — it was already Kraken-native and full-span. Derived spans (all three
symbols identical to the minute): **5m** 209,125 candles, **15m** 69,708, **1h** 17,427,
**4h** 4,356 — all 2024-10-01T00:00Z → 2026-09-27T03:00-03:05Z (0 gaps; every bucket that
should exist over the full 1m span exists, since the 1m series itself has 0 gaps).
`scripts/research/capture-binance-1m.js` and `manifest.json` are updated to match
(`derivedFrom1m: true` per timeframe); the swing:study and L0 reruns below are the
corrected ones. Everything above the fold that still says "copied verbatim" is superseded.

(`scripts/replay.js` `closeTimeOf`), not Binance's raw close-time field (`open + 59_999`).

writes `manifest.json` (counts, spans, and the Binance/derived-vs-Kraken overlap
validation below).

`api.binance.com` returned HTTP 451 (geo-block) from this environment on every call;
every request actually served came from the `data-api.binance.vision` fallback.

## 2-year rerun — `scripts/replay-rules.js --variant L0` (corrected fixture)

**Methodology note (why `--step 5`, not the default `--step 1`):** `replaySymbol`
(`scripts/replay.js`) calls the full production `buildAt` once per clock close (1-minute
clock) and keeps every resulting line in memory for the final report. A first attempt at
the literal default (`node scripts/replay-rules.js --variant L0 --history
test/fixtures/history/deep2y-2026-09-26`, no `--step`) ran for 7,982,756 ms (~133 min)
against the corrected fixture's genuinely-2-year eligible window (~522 days once `1d`'s
own 200-candle warmup clears, ~2025-04-23 onward — see below) and then crashed with
`FATAL ERROR: ... JavaScript heap out of memory` at Node's default ~4.3 GB old-space limit,
before it could print a report or write `--out`/`--summary`. Re-run with
`node --max-old-space-size=20480 scripts/replay-rules.js --variant L0 --history
test/fixtures/history/deep2y-2026-09-26 --step 5 --out ... --summary ...` (this machine has
36 GB RAM) completed cleanly in 3,289,640 ms build time (~55 min wall). `--step 5` samples
every 5th 1-minute close instead of every one — a disclosed 5x coarser sampling of the
same eligible window, not a shorter window; every other number below is from that run.

```bash
node --max-old-space-size=20480 scripts/replay-rules.js --variant L0 \
  --history test/fixtures/history/deep2y-2026-09-26 --step 5 \
  --out <scratch>/L0.calls.jsonl --summary <scratch>/L0.summary.json
```

Eligible window actually scored: `1d`'s 200-candle warmup (from its 2024-10-05 Kraken
start) is now the binding constraint across all six timeframes (5m/15m/1h/4h reach full
2024-10-01 coverage immediately per the derivation above, well before 1d clears warmup) —
first eligible close lands ~2025-04-23, so this run covers 2025-04-23 → 2026-09-27
(~522 days), a genuine ~6.1x longer window than the 85.5-day study, not the ~89-day window
the pre-correction fixture would have silently produced.
